**Contracts**:
- The 23 `reference-initial-*.mp3` files MUST play the initial's own call sound (呼读音), never the example word; card example hanzi (八/跑/哥 …) are display-only and must not be read into these files. Their live sha256 is locked by `public/audio/pinyin/reference-initial.sha256`.
- The 24 `reference-final-*.mp3` files MUST play the standalone Finals sound in a stable first tone, matching the Finals card label rather than a full example-word reading. Their live sha256 is locked by `public/audio/pinyin/reference-final.sha256`.
- The 16 `whole-syllables/reference-whole-*.mp3` files MUST match the approved numbered Whole Syllables files and first-tone card readings. Their live sha256 is locked by `public/audio/pinyin/reference-whole-syllable.sha256`.
- The five `reference-tone-[1-4]-<sha256 prefix>.mp3` and `reference-tone-neutral-<sha256 prefix>.mp3` files MUST play the approved `mā/má/mǎ/mà/ma` recordings respectively (neutral is the independent `ma` recording, NOT a reuse of `mā`). Each filename embeds its own sha256 short prefix so the tone URLs change whenever the audio content changes. Their live sha256 is locked by `public/audio/pinyin/reference-tone.sha256`.
- These manifests are enforced by `src/content/pinyin/course.test.ts`; editing a contracted file without updating the matching manifest turns the test red.

**Cache busting**: these audio files are served with `Cache-Control: public, max-age=86400`, so browsers hold them for 24 h, and Vercel's edge cache ignores query strings. The five tone files therefore embed their content hash in the **physical filename** (`reference-tone-1-6470708c.mp3`), so any recording change produces a brand-new URL = brand-new browser and CDN cache key; the old files are deleted so no path can serve stale bytes. The filenames in `src/content/pinyin/lesson1.ts` flow straight through the pinyin course JSON (`pkg/pinyincontent/data/pinyin_course.json`, regenerated by `npm run content:pinyin:check`). `src/content/pinyin/course.test.ts` locks each tone card URL to a filename that embeds the manifest hash prefix, so the version can never go stale: **if the tone audio files change, regenerate the sha256 manifest with the new hashed filenames, update the five tone card URLs, and run `content:pinyin:check`**.

If these assets are regenerated, keep the existing content paths unless a coordinated content/test update changes the naming convention.
